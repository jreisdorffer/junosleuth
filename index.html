Junosleuth

Forensic acquisitions for Juniper Junos routers, built to preserve volatile state, Routing Engine evidence, selected files, core dumps, and optional process memory before offline analysis.

View on GitHub Quick start

Core capabilities

  • Junos CLI evidence platform, routing, interfaces, processes, logs, configuration
  • Bash and PowerShell collectors run from Windows, macOS, or Linux forensic workstations
  • Raw output preservation original SSH stdout plus analyst-facing cleaned copies
  • Optional deep collection OS shell, files, cores, JMRT, and targeted live memory

Quick start

Choose Bash or PowerShell

Bash 
./junosleuth.sh -H 192.0.2.10 -u iruser -o /secure/evidence
PowerShell 
.\junosleuth.ps1 -HostName 192.0.2.10 -UserName iruser -OutputBase C:\Evidence

Collection surface

Built for evidence preservation

01

Junos state

Captures platform, hardware, uptime, users, alarms, processes, connections, interfaces, routing, storage, commits, configuration, and logs.

02

Raw and clean output

Stores original SSH stdout separately from analyst-facing copies, preserving login notices while keeping review output readable.

03

Optional shell evidence

Adds OS-level process, socket, mount, filesystem, writable-directory, user, and `/proc` metadata where permissions allow.

04

File and core acquisition

Mirrors selected remote paths under the evidence package and records remote and local SHA-256 values for transfer integrity.

05

JMRT in warn mode

Records Juniper Malware Removal Tool quick-scan and integrity-check output without deleting files or stopping processes.

06

Targeted memory

Explicit, experimental PID-based live-memory collection reads readable mapped regions without staging memory data on the router.

Operational flow

Collect first. Analyze offline.

  1. Detect

    Identify SSH landing mode, platform family, and collection boundaries.

  2. Preserve

    Capture volatile Junos state, logs, shell evidence, and selected files.

  3. Verify

    Record manifests, transfer hashes, stderr, and final package checksums.

  4. Analyze

    Perform IOC matching, timelines, YARA, and deeper review away from the router.
